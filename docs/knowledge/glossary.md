# 知识库领域用语

本表随设计访谈更新。实现代码应使用这里的词，避免「知识库 / RAG / 文档库」混称。

| 用语 | 含义 | 不是 |
|------|------|------|
| **知识库** | 用户创建的、可命名的资料集合。有自己的源文件副本和检索索引。应用内可有多个。embedding / topK / 匹配度阈值 / 分块参数 / 文档处理器是全应用一份，不按库。 | 单次对话附件；MCP memory；技能目录 |
| **条目** | 知识库里的一条来源。V1 类型只有 `file` 与 `note`。 | 分块；检索命中 |
| **文件条目** | 用户加入的普通文件。加入时拷贝进该库在 `userData` 下的目录，之后以副本为准。 | 对话输入栏的一次性附件 |
| **笔记** | 写在某个知识库内部的 Markdown 正文（标题 + 内容），不属于独立笔记 App，也不能脱离所属库单独存在。 | 磁盘上的 `.md` 文件条目（那是文件） |
| **文档处理器** | 把 PDF 转成 Markdown 的可插拔能力。V1 仅 `mineru`（官方 API）与 `open-mineru`（自托管）。全应用只选一个；凭证与端点在设置 → 文档处理中配置。未配置时 PDF 入库失败。 | embedding 模型；本机 OCR；`local-document` |
| **预处理** | 条目在 embedding 之前的文本化：纯文本/Markdown 直接读取；需处理的格式走文档处理器。 | 分块；向量化 |
| **分块** | 将预处理后的文本按 Markdown 结构切成片段。`chunkSize` / `chunkOverlap` 全局可配（默认 1024 / 200），所有库共用。 | 条目本身；按库不同的切分 |
| **检索范围** | 某次对话 topic 或终端助手会话里，用户勾选的知识库集合。未勾选则不检索。V1 没有全局默认库。 | 助手级绑定上限（Cherry 有，本产品 V1 无） |
| **预检索注入** | 普通对话（`chat:send`，无工具）在发送前按用户问题检索，把命中片段写入模型上下文。 | 智能体工具调用 |
| **知识库工具** | 智能体 / 终端使用的 `kb_search`、`kb_read`，由模型决定何时搜、是否读原文。勾选了至少一个知识库时自动带上。 | 静默 RAG；智能体设置里的普通工具开关 |
| **条目状态** | `pending` / `processing` / `completed` / `failed`。进程退出时未完成的条目标 `failed`，需用户点重新处理。 | 后台自动续跑的 Job |
| **索引库** | 每个知识库一份 SQLite（sqlite-vec），只服务该库的向量检索。 | 全局共用一个向量表 |
| **来源引用** | 普通对话回答下可点开的检索出处（库名 + 文件/笔记标题）。注入的片段只进当次 API 请求，不整篇写入会话记录。 | 对话附件；工具结果全文 |
| **召回测试** | 在当前知识库里输入问题，走与对话相同的向量检索，展示命中分块与余弦分数。用来检查索引是否可用。不写入对话，也不改检索范围。 | 对话预检索注入；带金标的 IR recall@k 评测 |
| **kb_search / kb_read** | 智能体工具。前者按当前检索范围做向量检索并返回带 `itemId` 的片段；后者按 `itemId` 读预处理全文（过长截断）。 | 文件系统 Read；联网搜索 |
| **匹配度阈值** | 全局余弦相似度下限。检索先取候选分块，分数低于此值的视为不相关：不注入对话、不作为 `kb_search` 命中。默认 0.5（50%），0 表示不过滤。改此项不重建索引。 | topK；rerank 分数 |
| **全局检索配置** | 全应用一份：embedding 模型、`topK`、匹配度阈值、`chunkSize`、`chunkOverlap`。改 embedding 或分块必须重建所有库的索引。 | 单库 RagConfig；每库一个 embedding |
