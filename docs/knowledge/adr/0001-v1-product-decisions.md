# ADR 0001 — 知识库 V1 产品决策

- 状态：已采纳（访谈第 1 轮）
- 日期：2026-09-05
- 范围：DesktopFairy 知识库第一版；参考 Cherry Studio，不复制其目录/链接/分组/JobManager 全量复杂度

## 背景

应用已能策展 embedding / rerank 模型，但没有笔记、文档入库、向量索引或检索入口。用户需要：多个知识库、对话与终端可多选检索、V1 只支持普通文件和笔记、文件经文档预处理再 embedding。

## 决策

1. **管理入口**：ChatApp 第四个顶栏 Tab「知识库」（与对话 / 终端 / 设置并列，keep-alive）。embedding 模型仍在「设置 → AI 模型」策展。
2. **笔记**：只存在于某个知识库内，库详情中新建/编辑 Markdown。不做独立笔记模块。
3. **检索双路径**：
   - 智能体与终端：内置 `kb_search` / `kb_read`（可引用、可追问原文）。
   - 普通对话：发送前预检索并注入上下文，否则「对话可选知识库」无效。
4. **Embedding**：~~每个知识库创建时绑定一个 embedding 模型~~ **已由 [0004](./0004-global-rag-config.md) 取代**：全应用共用一个 embedding 模型。
5. **文件保管**：加入时拷贝到 `userData` 下该库目录。库自包含；原文件删除或修改不影响已入库副本（除非用户显式重索引/替换）。
6. **文档处理**：V1 即可插拔文档处理器。PDF 未选处理器则失败，见 [0002](./0002-ingest-index-retrieval.md)、[0003](./0003-chunking-ui-tools.md)。
7. **检索范围**：无默认知识库。勾选持久化在对话 topic 上，见 [0002](./0002-ingest-index-retrieval.md)。

## 刻意不做（V1）

- 目录递归导入、URL/网站、知识库分组
- 独立笔记 App、跨库共享同一笔记
- 助手对象上的知识库绑定上限（Cherry 的 assistant ceiling）
- 全局默认知识库

## 后果

- ChatApp 的 `AppView` 增加 `knowledge`，须保持四页同时挂载。
- 主进程需要新的知识库服务、文件副本存储、embedding 调用、检索 IPC；智能体工具目录要增加 kb 工具。
- 普通对话与智能体看到的「用库」体验不同，UI 需要让用户理解当前后端。
- 引入文档处理器后，入库可能是分钟级外部 API，索引状态与失败必须对用户可见。
